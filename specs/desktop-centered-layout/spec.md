# Spec

## 基本信息

- 功能名称：桌面居中棋盘布局
- 对应 Proposal：`specs/desktop-centered-layout/proposal.md`
- 当前状态：approved
- 最后更新：2026-07-05

## 问题定义

主游戏页面需要以棋盘为视觉和空间中心，在桌面视口中保持棋盘水平居中并尽可能放大，同时将辅助信息重新分配到左右两侧。

## 用户故事

- 作为：桌面端玩家
- 我希望：棋盘始终处于屏幕中心且尽可能大
- 从而：可以把注意力集中在主要游戏区域，并清晰查看左右辅助信息

## 功能行为

### 主流程

1. 页面加载时根据桌面视口宽高计算棋盘 cell size。
2. 主布局分为左侧信息区、中间棋盘区、右侧 samples 区。
3. 中间棋盘区固定为棋盘 canvas 宽度，左右侧栏使用对称可用空间，保证棋盘水平居中。
4. 左侧信息区显示得分、next 模块和操作示意。
5. 右侧 samples 区只显示 sample 列表。
6. 玩家调整浏览器窗口大小后，页面应重新计算布局尺寸，并同步刷新棋盘、next 和 samples 的 canvas 尺寸。

### 自适应规则

1. 棋盘尺寸优先受视口高度限制，确保完整棋盘可见。
2. 当视口较宽时，棋盘应随高度尽可能大。
3. 当视口较窄时，棋盘尺寸需要给左右侧栏保留最低可用宽度。
4. 左侧内容在高度充足时纵向排列；高度不足时压缩间距和组件尺寸。
5. samples 区根据可用宽度自动换行展示。
6. 在 `1272 × 432` 等极矮桌面视口下，棋盘仍必须完整显示在可视区域内。
7. 极矮桌面视口下，左侧得分、next 和操作示意应切换为紧凑尺寸；如果仍然不足，优先允许左侧内部滚动，不得裁切棋盘。

### 异常流程

1. 如果视口过小，cell size 使用最低保护值，页面允许侧栏内容内部滚动。
2. 如果 welcome 覆盖层显示，主布局仍保持初始化尺寸，不影响开始游戏。
3. 如果游戏已经开始，窗口 resize 后应保留当前游戏状态，仅重建渲染尺寸和重绘当前画面。

### 空状态/加载态/错误态

- 加载态：不涉及
- 空状态：samples 挂载前右侧区域为空但保留布局
- 错误态：不涉及
- 重试机制：不涉及

## 验收标准

- [ ] 桌面视口下棋盘水平中心应接近视口水平中心。
- [ ] 棋盘完整显示，并在高度允许范围内尽可能大。
- [ ] 左侧显示得分、next 和操作示意。
- [ ] 右侧只显示 samples。
- [ ] 左侧内容在不同桌面高度下不会遮挡棋盘。
- [ ] `1272 × 432` inner 视口下棋盘完整显示，页面不出现主文档滚动，棋盘中心仍接近视口中心。
- [ ] 浏览器窗口大小变化后，棋盘、next 和 samples 使用新的 cell size 重新渲染，且当前游戏状态不被重置。
- [ ] samples 在右侧区域内换行展示，不挤压棋盘居中。
- [ ] lint、format、build 通过。

## 非功能要求

- 性能：resize 处理应按帧节流，不引入每帧常驻布局计算。
- 可维护性：布局尺寸集中在 `App.vue` 的计算函数和 CSS 变量。
- 可测试性：通过构建和桌面视口截图/DOM 检查验证。
